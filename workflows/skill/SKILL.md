# 流程转 skill

把已验证可行的工作流程或经验教训，收成任何助手都能用的通用 skill。

## 什么时候转
- 同一套多步流程会被重复做
- 有明确的成功标准与停止条件
- 有可复用的踩坑、检查点或审批节点

## 不要转
- 一次性、与具体人/频道/仓库绑定的临时任务
- 还不稳定、仍在试错的流程
- 纯知识问答（不是可执行步骤）

## 转换步骤
1. **收集源材：** 原始流程说明、成功案例、失败案例、必须避开的错误。
2. **抽象化：** 删掉助手名、群名、仓库地址、个人账号等专属信息；这些留给 routine 或当次对话。
3. **写 description：** 用一句「何时使用」，让读者能判断是否适用。
4. **写 body：** 按顺序列出可执行步骤、成功标准、常见失败与处理、需要用户确认的节点。
5. **落盘：** 用 UpdateSkill 写入；用 `[name](sand-workflow:<id>)` 在聊天里提及。
6. **分发：** 新 skill 或重要更新后，在相关群里用短消息说清：适用场景、谁该用、如何调用；不要刷屏。

## 质量检查
- 步骤能独立执行，不依赖某次对话上下文
- 没有抄工具名、内部 ID、临时路径
- 与已有 skill 不重复；重复则合并或改写旧的
