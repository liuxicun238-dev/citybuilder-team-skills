# 发布模型资产到 GitHub

## 交付目标
为一个物体或区域提供一个完整 ZIP、明确版本、质量状态和可用下载链接。大二进制使用 Releases；说明和可独立使用的 skill 可作为仓库文本文件。不要把上传成功当成美术验收通过。

## 最短路径
1. 确认用户指定的 owner/repo、当前可见性、允许上传的文件范围。仓库 README 写“私人”不能证明仓库是私有。公开发布需有相应授权，历史授权不自动覆盖其他项目。
2. 先检查现有 Release/标签，避免重复；优先使用已连接且支持所需操作的接口。
3. 确认是否真正具备 Release 附件上传能力。仓库写权限不代表接口支持 Releases；连接器授权不代表浏览器已登录，也不代表 gh CLI 已认证。不要提取令牌、读取浏览器凭据或自行新建访问令牌。
4. 使用已有会话打开目标仓库的 Releases 页面。用户说已登录后，先重新观察页面，不要再启动登录表单。能打开新建 Release 表单并看到目标仓库，才算有可用发布会话。
5. 对已经验证的交付物制作公开副本，进行下述轻量检查；保持原始成果不变，不为上传重新建模或重渲染。
6. 创建描述性的标签，上传一个完整 ZIP，等待附件显示文件名及大小，然后发布。试验资产标为 Pre-release。
7. 发布后重新读取页面，确认附件名称、尺寸、下载 URL 和 SHA-256。与本地哈希一致后交付链接；若远端不提供哈希，在可用条件下下载回验。未回验的项目明确标注。

## 语义命名
- 发布标题可使用中文，例如“钢门焊接铰链｜模型、材质与制作技能 v0.1 实验版”
- 附件使用 ASCII 描述性名称，避免服务过滤中文后变成无意义字符。例如：
  welded-steel-door-hinge_models-textures-skill_v0.1-experimental.zip
- 标签例如 welded-steel-hinge-v0.1-experimental
- 文件名表达物体、内容、版本；不要使用随机编号、final-final 或只写日期
- 包内目录、说明可保留中文。检查网页实际保存的附件名，不只检查本地文件名
- 不拆成多个小分卷，不用仓库自动生成的 Source code ZIP 冒充模型附件
- 不覆盖已有版本附件。若需要替换，先确认目的，记录变更；默认创建新版本

## 公开前检查
- 检查 ZIP 能正常解压；模型、贴图、预览、脚本和说明齐全
- 检查许可证和第三方素材分发条件；仅用于研究的产品参考照片不随包分发
- 检查文本、图片元数据、Blend 和 FBX 中的凭据、个人信息及无关机器路径
- 不能仅靠 grep 宣称无敏感信息；同时检查格式结构及实际内容
- Blender 图片路径使用包内相对路径；清理渲染输出路径、保存的文件浏览器目录等不必要环境信息
- FBX 即便选择 RELATIVE，也可能仍含绝对路径字段。用格式解析器或重新导出清理，不能破坏二进制布局进行任意字符串替换
- 修改后重新打开 Blend、检查贴图存在性；重新导入 FBX，对比网格数、UV、尺度等必要指标
- 生成包内文件清单和哈希；最终 ZIP 再计算 SHA-256。不要把 ZIP 自身放进自身清单
- 记录实际通过/失败项，例如“可复现通过，视觉未达标，尚未在 UE 验证”

## 浏览器上传操作
使用当前环境提供的浏览器工具，并先读取其上传文档。不要使用旧会话的元素编号。

若提供文件选择器 API：
1. 先等待 filechooser 事件
2. 点击页面实际的附件上传控件
3. 给选择器传入完整 ZIP 路径
4. 读取新页面状态，等待上传中提示消失并出现附件条目
5. 确认附件名、版本标签、标题、说明、Pre-release 状态，再点击发布
6. 读取正式发布页，确认真实下载链接

只通过页面可见状态建立操作目标，不通过未授权网络调用或脚本提取登录态。若上传需要额外确认，报告正在等待确认；不要把此时状态写成“上传完成”。

## 卡住时的快速恢复
- 将长工具调用设置为可提前返回的执行方式，保存运行单元/会话 ID，避免一个调用吞掉所有进度汇报
- 没有返回结果时，区分“等待批准”“工具没有响应”“实际文件上传中”，不要猜上传百分比
- 用户已经完成登录而旧登录请求仍等待时，先核查或结束旧等待，再从当前浏览器重新观察；不要重复索要密码
- 旧标签失效时，在原选定浏览器内重新获取标签或打开目标发布页，不随意切换到用户另一台电脑
- 若同一执行会话连简单本地读取也卡住，报告执行故障；由可正常工作的会话接续既有成果。接续前检查远端是否已成功，防止重复发布
- 不连续盲重试、不重新生成资产、不绕过拒绝或安全检查。需要登录、权限或服务恢复时，给出明确阻塞和最小下一步

## 进度及费用
遵守当前用户要求的汇报周期。若要求每两分钟汇报，使用短调用并主动检查时间；没有新进展也报告真实卡点，完成或暂停后停止工作进度汇报。不要让等待上传或批准导致漏报。

在需要启动可能消耗用户额度的额外任务前，说明已知影响；看不到计费数据时不承诺免费、不编造扣量。本 skill 不授权新建执行任务或扩大费用。

## 已验证案例
2026-10-17，45,458,168 字节的铰链完整包经网页登录的 Releases 页面上传成功。GitHub 附件显示的 SHA-256 与本地一致。中文附件名被过滤，改为描述性英文名称后发布成功。此案例验证交付流程，不证明模型达到 3A 质量，也不保证后续服务额度和限制不变。
